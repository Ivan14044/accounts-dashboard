# Улучшения Dashboard — 7 сентября 2026

Исходная версия: `a7817f4`. Изменения подготовлены в `codex/dashboard-performance-design` по согласованному OpenSpec-предложению `update-dashboard-performance-design`.

## Что изменено

- Удалены Google Fonts stylesheet и CSS import. Системная типографика отображает кириллицу сразу; у входа версия статики привязана к изменениям файлов вместо текущей секунды.
- noUiSlider 15.7.1 поставляется локально с лицензией, сохраняя порядок исполнения.
- Код импорта и запрос его конфигурации загружаются при первом открытии окна. Есть состояние загрузки, защита от повторной загрузки, восстановление кнопки и повтор после сетевой ошибки. Форма открывается после подключения обработчиков.
- Автообновление не накапливает timers/listeners, переживает недоступный localStorage, пропускает скрытую вкладку и открытый редактор строки, не отменяет чужой ручной запрос. Кнопка отражает состояние через aria-pressed.
- Виртуализация использует единый порог; обновление, пустой ответ и отмена редактирования не теряют данные. Сохранённая правка обновляет данные, из которых строки повторно создаются при прокрутке.
- `refresh.php` отпускает сессию после авторизации и сохранения активности. Статистика продолжает учитывать маркер собственной недавней записи из сохранённого снимка сессии.
- Добавлена навигация между аккаунтами, избранным и корзиной с сохранением выбранной таблицы. Профиль доступен с клавиатуры. Упорядочены заголовки, статистика, фильтры, поверхности и обе темы; дополнительные фильтры остаются открытыми согласно существующему предпочтению владельца.
- Убраны постоянная пульсация подключения и задержки появления отдельных карточек. Reduced motion работает также для программной прокрутки. Исправлены мобильная пара «статус / размер страницы» и обрезанное поле даты в корзине.

## Сравнимые замеры

По пять чередующихся прогонов каждой версии, Chrome headless, viewport 1440×1000, CPU ×4, RTT 80 ms, download 10 Mbps. Новый browser context и отключённый HTTP cache на каждый прогон. Обе версии используют собранные бандлы, один Docker PHP/MySQL-стенд и одну визуальную БД с 1200 синтетическими аккаунтами (1180 активных). База для integration-тестов отделена от визуальной. PHP development server не применяет Apache gzip/.htaccess: transfer ниже не равен production payload.

| Метрика, медиана | До | После |
| --- | ---: | ---: |
| LCP | 1160 ms | 1148 ms |
| CLS | 0.08447 | 0.00659 |
| DOMContentLoaded | 2199 ms | 2128 ms |
| Ресурсные запросы после navigation | 19 | 16 |
| Transfer ресурсов по Resource Timing | 1426742 B | 1392091 B |
| Сумма времени long tasks сверх 50 ms | 50 ms | 40 ms |

Основной измеренный выигрыш — стабильность раскладки: CLS уменьшился примерно на 92%. LCP практически одинаковый; обещания многократного ускорения страницы эти данные не подтверждают. Resource Timing может не раскрывать transfer внешних ресурсов без Timing-Allow-Origin. Последующие небольшие доработки состояния кнопки lazy loader, уведомлений и мобильных touch targets не включена в эту серию; её функциональность проверена отдельно.

Собственные бандлы после финальной сборки: CSS 195726 B, sync JS 494731 B, defer JS 78115 B. Исходный defer JS — 131641 B: начальный отложенный пакет уменьшился примерно на 41%. Размеры несжатые, со служебными разделителями сборщика. Это не процент ускорения всего сайта.

### Конкурирующие запросы сессии

На тестовой БД чтение accounts искусственно задерживалось `LOCK TABLES ... WRITE` на 2.5 секунды. Во время `refresh.php` выполнялся второй запрос `login.php` с той же сессией (ожидаемый ответ — redirect 302). Четыре PHP server workers:

- До: второй запрос ожидал 2018 ms.
- После: второй запрос ответил за 5 ms.

Этот эксперимент показывает устранение session lock, а не ускорение SQL. Реальные задержки зависят от запроса и хостинга. Сами SQL/индексы не менялись: уже реализованные покрывающие индексы и кеш статистики сохранены. EXPLAIN на тестовой БД подтвердил использование покрывающего idx_deleted_status для группировки статистики и PRIMARY/eq_ref для получения строк после выборки идентификаторов пагинации. План на 1200 строках не используется как доказательство поведения большой production-базы.

## Проверки

- Все 38 `tests/test_*.php` прошли на PHP 7.3 и 8.2; все PHP-файлы прошли syntax lint на 7.3.
- Все три `tests/integration_*.php` прошли на реальном MySQL 8.0 в отдельной тестовой БД.
- 20 поведенческих Node-тестов lifecycle, виртуализации и inline edit; отдельные тесты lazy import и session snapshot прошли.
- Проверены сборка ресурсов, манифест/порядок и fallback на исходники. Node syntax/behavioral tests добавлены в существующий CI job без изменения его имени.
- Браузер: главная, избранное и корзина на ширинах 360/390/768/1024/1440/1920 в светлой и тёмной темах; вход на 360/768/1440. Нет горизонтального overflow страницы; широкие таблицы прокручиваются внутри контейнеров.
- В браузере проверены поиск, пустая выдача и сброс, выбор строк, переключение тем, десять start/stop автообновления, первый/повторный импорт и retry после намеренно оборванной загрузки скрипта, выбор первого CSV-файла.
- Реальная серверная страница на 200 строках; отдельная клиентская проверка 500 синтетических строк: в DOM 29 видимых строк, отмена редактора сохраняет 500, прокрутка показывает дальние строки, переход 500 → 100 → пусто корректен. Серверный whitelist остаётся 25/50/100/200; поддержка страницы на 500 записей этим изменением не добавлялась.
- Проверены видимый keyboard focus, reduced motion и масштаб 200%; в мобильной touch-эмуляции — переключение Email-фильтра, меню профиля и доступность выхода. Прозрачные checkbox имеют доступные имена и видимый focus на переключателе.

## Практические ограничения

Это локальные лабораторные проверки Chrome, не полевые INP/FPS и не замеры production. Safari/Firefox отдельно не запускались. Внешние проверки аккаунтов не вызывались. CSV/TXT parser/export и мутации покрыты существующими PHP/интеграционными тестами; все варианты внешних операций в браузере не перебирались. Перед production-оценкой нужны данные реального хостинга и распределение запросов пользователей.

Для локальной пересборки: `php tools/build_assets.php`. На деплое существующий GitHub Actions обновляет ASSETS_VERSION и собирает ресурсы. Изменений схемы и миграций данных нет.

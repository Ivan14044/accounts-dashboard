# Решения

## Подход

Рекомендуется последовательное улучшение существующей панели. Альтернативы: только косметическая полировка дешевле, но оставляет lifecycle и загрузку; переписывание на SPA значительно расширяет риски и расходится с ограничениями shared hosting. Сохраняем PHP-шаблоны и API, измеряем и улучшаем критические пути.

## Визуальное направление

Строгий рабочий инструмент с хорошо различимыми уровнями информации: заголовок/контекст, статистика, фильтры, таблица. Нейтральный фон и поверхности, один основной акцент, тонкие разделители; семантические статусы имеют собственные цвета. Табличные числа, ясные подписи, предсказуемая плотность, единые размеры элементов. Шрифт обязательно поддерживает кириллицу; системный стек — исходный быстрый вариант, локальный лицензированный WOFF2 допустим при доказанной визуальной пользе.

Упорядочивать существующие CSS-токены и компоненты вместо добавления ещё одного глобального override-файла. Визуально проверить главную, избранное, корзину, вход, модальные окна, пустые/ошибочные/загружаемые состояния. Для каждой страницы нужны реальные скриншоты до/после на стенде.

## Адаптивность

Контрольные ширины: 360, 390, 768, 1024, 1440, 1920 px. Управление переносится по смысловым группам; важные действия доступны без hover. Большая таблица прокручивается внутри своего контейнера, страница не имеет непреднамеренного горизонтального overflow. Не превращать финансовые/учётные строки в декоративные карточки с потерей сравнения. Клавиатура, видимый focus, контраст и масштаб 200% входят в приёмку.

## Движение

Короткая обратная связь 120–180 ms, появление небольших панелей до 220 ms. Анимировать transform/opacity, не добавлять анимацию каждой строки большой таблицы. Избегать постоянного свечения/пульсации и тяжёлых backdrop-filter. `prefers-reduced-motion` отключает декоративное движение и программный smooth scroll; состояние загрузки остаётся понятно без движения.

## Загрузка и данные

Зафиксировать зависимости globals, последовательность config/init и библиотек. Делить пакет только после измерения CPU и покрытия. Отложенный модуль грузится один раз, первый клик не теряется, ошибка даёт доступный retry, повторное открытие не добавляет handlers. Fallback без собранных ресурсов остаётся работоспособным.

Сессия закрывается только после auth/timeout/CSRF и всех требуемых записей; после закрытия endpoint не должен рассчитывать на сохранение изменений `$_SESSION`. Проверить чтение, мутации и две параллельные операции одной сессии. Кеш не должен смешивать пользователей, таблицы или фильтры.

## Проверка и критерии

Сравнить минимум пять прогонов до/после при одинаковых данных и browser throttling; отдельно cold/warm cache. Записать медианы TTFB/LCP, размер передачи, long tasks и время обновления таблицы. Целевые ориентиры: LCP ≤2.5 s, CLS ≤0.1; interaction latency ≤200 ms в воспроизводимых сценариях, без представления лабораторного показателя как field INP. Для 60 Hz целевой бюджет кадра около 16.7 ms; проверять trace скролла и переключения фильтров. Ориентиры — критерии измерения, не обещание результата на любом устройстве.

Регрессии: фильтры и URL, пагинация, выбор «все по фильтру», inline edit, копирование, импорт/экспорт, отмена, избранное/корзина, custom cards, session expiry. CI: PHP lint и tests/test_*.php на 7.3/8.2, tests/integration_*.php с MySQL, JS syntax и реальные browser сценарии. Не считать пропущенные интеграционные тесты успешными.

## Риски и откат

TDZ/order при разделении JS → тест source/bundle и первого действия. Density/виртуальная высота → scroll trace на всех режимах. CSS refactor → snapshots обеих тем. Session close → тест сохранения состояния. Выполнять небольшими обратимыми изменениями; откат через возврат соответствующего изменения кода. Миграций данных по умолчанию нет.

## [Не выпущено]

### Изменено
- **CSS и JS дашборда собираются в бандлы.** Страница тянула 43 своих файла
  (35 JS + 8 CSS), теперь три: `assets/build/core.css`,
  `dashboard.sync.js`, `dashboard.defer.js`. По брутли — как реально отдаёт прод —
  166 373 → 134 323 байта (−19,3 %). Список файлов и их порядок переехали в единый
  манифест `includes/AssetBundles.php`; собираются бандлы шагом деплоя, а не в
  рантайме. Если бандла на сервере нет, шаблон отдаёт исходники по одному —
  сломанная сборка не роняет страницу.

### Исправлено
- **Строка таблицы «прыгала» при наведении мыши.** Панель кнопок
  (редактировать / копировать / показать пароль) вставлялась прямо в поток
  ячейки, а таблица считает ширину колонок по содержимому. Из-за этого каждое
  наведение меняло ширину колонки и переставляло всю таблицу целиком: при
  проводке мыши вдоль строки сдвигалось 35–42 ячейки, максимум на 73,7 px, и
  каждый переход между ячейками стоил 2,6–12,6 мс пересчёта раскладки при
  бюджете кадра 16,7 мс. Теперь панель висит над правым краем ячейки вне потока:
  при том же замере — 0 сдвинутых ячеек, 0 px. Панель больше не заезжает и на
  соседнюю колонку (узкие колонки перекрывались на ~12 px).
- **Ячейка навсегда «толстела» после каждой правки.** Редакторы обычного поля и
  пароля сохраняли содержимое ячейки, чтобы вернуть его после сохранения или
  отмены, — и захватывали в этот снимок ещё и панель кнопок. При восстановлении
  её копия вклеивалась в ячейку намертво: ячейка `last_name` росла со 108,9 до
  174,3 px, `password` — со 102,8 до 213,5 px, и в ней оставался второй комплект
  кнопок. Эффект накапливался с каждой отредактированной ячейкой.
- **Отмена действия (undo) не показывала результат и не обновляла таблицу.**
  После успешного отката модуль падал на `Toast.success(...)`: голое имя `Toast` —
  это класс из `assets/js/toast.js`, а не экземпляр `window.Toast` с методами.
  Ошибка улетала в `catch`, где падала повторно, и до обновления данных дело не
  доходило. В БД откат при этом происходил — то есть пользователь видел старые
  данные и думал, что отмена не сработала.
- **Свайп по карточке статистики на телефоне молча ничего не делал.** Причин было
  две, каждая сама по себе фатальная: жесты вешались на класс `touch-card`,
  которого нет ни в одной разметке (слушатели не создавались вообще), а решение
  «что делать со свайпом» принималось по атрибуту `data-card-type`, который
  сервер не рендерит. Теперь свайп влево по карточке статуса применяет фильтр по
  этому статусу без перезагрузки страницы, а по карточке «Всего» — показывает
  подсказку. Кастомные карточки, появляющиеся уже после загрузки, работают без
  переинициализации.

## [2.3.0] - 2026-08-08

Полный аудит проекта ([docs/AUDIT_2026-08-08.md](docs/AUDIT_2026-08-08.md)) и
работа по его итогам. Каждая правка подтверждена тестом и живой проверкой.

### Исправлено
- **Выгрузка истории изменений портила значения с обратными слэшами.**
  `admin_logs.php` писал CSV дефолтным `fputcsv` (escape='\\'), из-за чего
  cookies, token и пути не переживали обратное чтение. Запись CSV теперь одна на
  проект — `includes/Csv.php`; формат выгрузок не менялся.
- **Ошибка в запросе отдавалась как «500, произошла ошибка сервера».** Кривой
  JSON или отсутствующий CSRF теперь дают понятный `400` и JSON, а не
  HTML-страницу; страница ошибки при 4xx говорит «Некорректный запрос», а не
  отправляет искать поломку в логах. В логе больше нет бессмысленного
  «Invalid JSON format: No error» — пишется настоящая причина.
- **С телефона нельзя было пользоваться пагинацией:** список страниц вылезал за
  экран и обрезался. Теперь переносится по строкам.
- **Кнопка «Перейти» обрезала свою подпись** на всех размерах экрана.
- **Пустая таблица роняла страницу** на PHP 8 (`count()` без аргумента).

### Изменено
- Дашборд запрашивает кастомные карточки один раз за загрузку вместо трёх.
- Модули подписываются на обновление таблицы через
  `DashboardRefresh.onAfterRefresh()` вместо переопределения глобальной функции —
  сбой одного модуля больше не ломает остальные.

### Безопасность
- Закрыты по HTTP служебные каталоги `includes/`, `tools/`, `sql/` и файлы
  `*.sql`. До этого `sql/create_all_tables.sql` отдавал схему БД целиком.
- Отключён показ текстов PHP-ошибок посетителю: прод показывал Parse error
  вместе с абсолютным путём на сервере. Логирование сохранено.

### Для разработчиков
- Обнаружено и зафиксировано: **PHP на проде старее 7.4**. Гейт `lint` теперь
  линтует на 7.3 (нижняя граница) и гоняет тесты на 7.3 и 8.2 — раньше
  синтаксис 7.4 проходил проверку и падал на живом сайте.
- Тестов в CI-гейте стало 8 вместо 5: добавлено покрытие импорта и записи CSV,
  выбора HTTP-кодов, пустой выдачи таблицы. Диагностический скрипт, который
  печатал «FAIL», но всегда завершался успехом, убран из гейта.
- Удалён мёртвый код, который при этом уезжал на прод:
  `assets/js/features/custom-cards.js` (дубль логики карточек, не подключался ни
  одним шаблоном), `deploy.php` (FTP-загрузчик, дублировал GitHub Actions и
  требовал несуществующих переменных окружения) и `build_assets.php` (сборщик
  бандла, который ни одна страница не подключает). Все три восстанавливаются из
  истории git.

## [2.2.0] - 2026-07-04

### ⚡ Плавность панели (замеры на стенде: MySQL 10k строк, headless Chrome)

#### Изменено
- **«Тонкая» разметка строк таблицы** — кнопки копирования/редактирования больше
  не рендерятся в каждой ячейке (их даёт одна плавающая hover-панель,
  `assets/js/modules/cell-actions.js`), а полные значения длинных полей
  (cookies, token и т.п.) не кладутся в HTML целиком — подгружаются по
  требованию (`field_value.php`) или берутся из данных строки в JS.
  Замер: строка 30 КБ → 16 КБ; HTML страницы 1.7 МБ → 0.95 МБ (50 строк),
  6.4 МБ → 3.4 МБ (200 строк); стоимость шага виртуализации при скролле
  (рендер+layout) 41 мс → 15 мс (медиана) — скролл при 200/стр перестал дёргаться.
  Разметка синхронно изменена во всех трёх рендерерах: `templates/partials/table/rows.php`,
  `table-module.js`, `dashboard.js`.
- **Debounce 250мс на чекбоксы статусов и быстрые фильтры** — серия быстрых
  кликов даёт один запрос вместо запроса на каждый клик (замер: 4 клика → 1 запрос).
- **Bootstrap и Font Awesome теперь локальные** (`assets/vendor/`) — убраны
  блокирующие рендер CDN-запросы (~0.5 с) и зависимость от cdn.jsdelivr/cdnjs.
- Автообновление (30 с) не дёргает сервер в фоновой вкладке (visibilitychange);
  `history.php`/`log.php` больше не ломают кэш браузера `?v=time()`.

#### Исправлено
- **Просмотр полного значения длинного поля по клику не работал** (обработчик
  `[data-full]` жил в неинициализируемом классе `Dashboard`) — просмотр
  реализован заново в `cell-actions.js` и работает, включая подгрузку значения.

### ↩️ Отмена последнего действия (undo)

#### Добавлено
- **Кнопка «Отменить последнее»** в тулбаре дашборда — показывает последнее отменяемое
  действие текущего пользователя и откатывает его с подтверждением
- **Журнал действий `user_actions`** — каждая мутация (смена статуса, правка поля,
  массовые операции, удаление в корзину, массовый перенос) фиксируется как одно
  логическое действие; строки `account_history` связываются через `action_id`
- **`undo.php`** — API: `GET` последнее отменяемое действие, `POST` откат
- **`includes/UndoService.php`** — логика отката: оптимистичная проверка
  (строки, изменённые после действия, не трогаются), чанки по 500,
  чувствительные поля (`[СКРЫТО]`) пропускаются, повторный откат блокируется атомарно,
  сам откат логируется как действие типа `undo` (не отменяем)
- **Тосты с кнопкой действия** (`toast.js` — опция `action`), предложение отмены
  в тосте после операций
- Тесты: `tests/test_undo_plan.php` (без БД), `tests/integration_undo_mysql.php`
  (полный путь на реальном MySQL, запуск через Docker — см. заголовок файла)

#### Исправлено
- **AuditLogger::logBulkChange читал старые значения всегда из `accounts`** —
  для других таблиц (`?table=xxx`) история писалась с неверными old_value.
  Теперь таблица передаётся явно
- **Аудит массового переноса не писался вовсе** — `logBulkChange` вызывался после
  UPDATE внутри транзакции, старые значения совпадали с новыми и все строки
  отбрасывались как «без изменений». Лог перенесён до UPDATE
- **Аудит «удалить все по фильтру» терял строки** — ID собирались после удаления
  эвристикой «deleted_at за последнюю минуту LIMIT 100» (максимум 100 строк,
  возможен захват чужих удалений). Теперь ID собираются до удаления, без лимита
